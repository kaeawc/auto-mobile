# Session-owned virtual BLE peripherals

`blePeripheral` is a plain daemon tool with session ownership enforced at ingress and at handle lookup. It requires a live session, defaults to that session's device and refuses another device target. Multiple handles are supported. GATT state is ephemeral and excluded from device mutation journaling and plan recording.

`BlePeripheralManager` owns a `BlePeripheralSidecar` per handle. A start registers ownership before awaiting provisioning. Session release/unbind aborts pending starts and kills every owned sidecar; daemon child-process cleanup closes admission and kills all remaining sidecars. Cleanup failures retain ownership for retry. Sidecar exit is confirmed through the shared child-process tracker, with bounded SIGKILL teardown. Request cancellation interrupts startup; successful peripherals remain until explicit stop or owner cleanup.

`PythonEnvProvisioner` uses the existing data-directory resolver, including `AUTOMOBILE_DATA_DIR`, under `ble-peripheral/venv`. An injected host command runner creates the venv and installs `bumble==0.0.236`, `grpcio==1.85.1` and `protobuf==7.36.2`. Concurrent starts share provisioning. The exact pin-set marker is written only after installation succeeds; changed pins reinstall, and a missing interpreter recreates the environment. Python packages stay outside the npm runtime graph. Missing Python and provisioning errors carry repair instructions; doctor warns because only BLE needs Python.

The checked-in Python asset is copied beside bundled TypeScript chunks into `dist/src/ble-peripheral.py`. The process client resolves either the source asset or that packaged sibling independently of the daemon's working directory. Python runs with isolated imports and unbuffered output. The first stdin JSON line contains the GATT configuration; subsequent lines carry numbered notify/status/stop commands. Stdout contains JSON events and acknowledgements: ready, advertising, connected, disconnected, status, notified, stopped and error. Commands have deadlines through the injected Timer; process failure, malformed output and pipe closure reject outstanding requests. Status includes advertised configuration, readiness, connections and subscribed characteristic UUIDs.

`BleTransportResolver` honors an explicit transport first. Otherwise the existing running-AVD advertisement reader correlates the emulator serial with a live PID, and the host process-table reader recovers the launcher's `-packet-streamer-endpoint localhost:<port>` argument. An explicit console port can identify a process without an advertisement. This works for a private netsimd retained across daemon restarts and avoids confusing the emulator's own gRPC port with netsimd's port. A valid private endpoint becomes `android-netsim:localhost:<port>`; no known private endpoint falls back to `android-netsim`. Unreadable or ambiguous identity is actionable rather than silently selecting the shared instance.

BatteryService reads from a mutable-level callback, including notification reads. Heart-rate measurements use the profile serializer and callback. Custom read/notify characteristics hold byte values. Advertising includes the local name and selected standard service UUIDs. A central connection pauses advertising; Bumble's `auto_restart=True` resumes it after disconnect. Subscription state is tracked per connection and characteristic, and removed on disconnect. A crash clears runtime state; clients start a new handle rather than automatically replaying peripheral state.
