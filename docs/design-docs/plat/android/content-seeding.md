# Android content seeding

`seedContent` is a device control with strict input and output schemas. The caller supplies a namespace matching `[A-Za-z0-9_-]{1,32}`; provider identity is `automobile.<namespace>`. Android content bindings reject colons in values, so the account tag uses a dot and shell-bound text rejects colons. The existing shellQuote helper protects each argument and the outer `sh -c` command; the adb executor receives argv directly and disables retries for writes.

Contacts use raw_contacts with account_name=automobile.<namespace> and account_type=dev.jasonpearson.automobile.contentseeder, then query `_id:account_name:account_type` and select the highest ID matching both fields. Before inserts, kind=account idempotently registers the namespace through the same AccountManager.addAccountExplicitly path as calendars. ContactsProvider purges raw contacts owned by unregistered accounts on account changes; using the registered account type is a persistence invariant across namespaces and kinds. Non-photo Data rows share one shell batch per contact. Names split at the final space, phones use mobile type, and emails use home type. Call logs batch inserts and carry the tag in subscription_component_name. Reset scopes provider queries and deletion to the namespace and account type; contact cleanup also includes the legacy account_type=automobile.<namespace>, while preserving unrelated account types with the same name; contacts use caller_is_syncadapter=true for physical removal. Shell deletions return no count, so before/after queries supply counts and confirm absence. No concurrent writer should seed the same namespace on the same device.

Optional photoPath is checked through an injected filesystem seam before any device writes: regular file, PNG/JPEG extension and magic, and a 524288-byte limit with a bounded read. Relative paths resolve against the daemon launch directory. The host pushes to /data/local/tmp/automobile.<namespace>.<rawId>.photo, then shell pipes the bytes to `run-as dev.jasonpearson.automobile.contentseeder sh -c` to create cache/automobile.<namespace>.<rawId>.photo. The app never directly reads shell_data_file, which SELinux may deny; run-as requires a debuggable APK and creates the file under the app uid with its app-data label. The photo broadcast carries kind=photo, namespace, rawContactId, and photoFile (only the exact namespace/id cache filename is accepted). The app verifies raw-contact account ownership, size and signature, then inserts a photo Data BLOB through ContentResolver with caller_is_syncadapter=true. This synchronous insert creates photo_id; the provider may also produce photo_file_id. App and host read-back require one positive photo identifier. Both sides delete the staged file after an attempt; host cleanup also runs after cancellation. Contact reset verifies absence of namespace photo Data rows after permanent raw-contact deletion and removes leftover staging files. Dots delimit staging namespace and id because dots are forbidden within namespace, keeping reset globs namespace-scoped.

Contacts, calendar, and SMS require the debug-only content-seeder application. The host checks package presence, installs with `-t` when necessary, and grants the SMS role plus READ_CALENDAR, WRITE_CALENDAR, READ_SMS, READ_CONTACTS, and WRITE_CONTACTS. The seeder declares Contacts permissions for photo writes and read-back. APK lookup uses AUTOMOBILE_CONTENT_SEEDER_APK_PATH, then the checkout's android/content-seeder/build/outputs/apk/debug/content-seeder-debug.apk. Missing APK errors name `./gradlew :content-seeder:assembleDebug`. Call-log-only requests bypass provisioning.

Explicit ordered SEED broadcasts carry namespace and kind. Calendar and SMS each send one items JSON batch; account, photo, and reset use string extras. The host converts ISO instants to Unix millisecond startMillis/endMillis/dateMillis values. Reset uses kind=reset and comma-separated calendar/sms kinds. The optional string extra dropAccount=true removes the shared account after data deletion; omitting kinds with this flag performs only account removal. kind=account needs only namespace and returns JSON with inserted=1 for a newly registered account or 0 for an existing account. SeedRequest validates the complete batch before provider writes. RESULT_OK data is JSON with inserted and removed counts; RESULT_CANCELED carries an error. The host reuses the broadcast envelope parser and rejects legacy URI responses.

Calendar accounts are named automobile.<namespace> with the registered seeder ACCOUNT_TYPE. Each requested calendar name identifies a separate calendar within the account. All-day boundaries must be UTC midnight, with exclusive DTEND; location is preserved. Calendar reset deletes events and calendars using the sync-adapter URI, preserving the account by default. Only a full namespace reset with no arrays requests account removal, after contact, calendar, call-log, and SMS deletes finish. Removing the shared account during a kind-specific reset would purge surviving contacts or calendars. SMS rows carry the tag in service_center and preserve the read flag. Provider enforcement determines SMS write authority; default-package/settings lookups are not reliable role oracles.

Reset operates on supplied kinds, including empty arrays, or all four when arrays are omitted. Every reset completes before any insertion begins. Contacts and call logs compare tagged row counts before insertion and after all provider writes, requiring growth by the requested count. Calendar and SMS query the inserted IDs before returning their verified counts; the host rejects counts that differ from the batch size. Counts describe confirmed rows; operations across providers are not transactional. Failures can leave partial data, so callers retry with reset. No automatic namespace release cleanup is claimed: session dispatch journals an opaque persistent mutation and uses baseline fallback for cleanup. The tool is disabled by default, plan relevant, destructive, and non-idempotent because append calls duplicate rows and role grants change device state. iOS is unsupported.
