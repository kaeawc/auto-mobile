ProtoViewer is a viewer for design prototypes that its user authors. A prototype is a validated, declarative JSON document: it describes layout, theme, motion and saved values, and the renderer's feature set is fixed in this binary. The app does not download, install or execute code that adds or changes its features.

The app works on its own: no other app, account or sign-in is needed. The library is empty on first launch until a prototype is imported.

To try the import flow:
1. Save the sample .automobile-proto file attached to this submission to the Files app, then tap it (or share it to ProtoViewer).
2. Choose ProtoViewer. The prototype is validated and added to the library.
3. Tap it to view it. Use the row menu to Relaunch, Reset or Share.

Reporting and hiding received content (guideline 1.2): a prototype someone else sent (opened from Files or shared to ProtoViewer) has Report and Hide in its row menu (long press or swipe left).
- Report opens a mail draft to automobile+coc@jasonpearson.dev with the prototype's name, content hash and how it arrived. The app sends nothing itself and attaches no prototype data.
- Hide asks for confirmation, then deletes the prototype and every copy of it, and hides copies received later on this device. Importing the same prototype again fails with "This prototype is hidden on this device".
- Settings > Report a problem shows the same contact address.
Prototypes the user made are never offered Report or Hide. Received prototypes carry no sender identity on iOS, so there is no one to block; hiding by content applies instead.

Network access for imported prototypes is off by default and is switched on only in the library settings, after a confirmation dialog. While it is on, the viewer shows a "Network on" band outside the prototype's bounds that the prototype cannot cover. A prototype's request actions send HTTP to the hosts it names. The app follows a redirect from such a host to any destination that passes the same destination checks as the original request (loopback, link-local and multicast addresses are refused), for at most five redirects and never from HTTPS to HTTP. A 307 or 308 redirect keeps the request's method and body, and the Authorization header is dropped when a redirect changes origin. Responses only fill the prototype's own data model; they cannot add components or behaviour.

Local Network: designers point prototypes at mock backends on their own development machine, which is on the local network. The Local Network prompt appears only after the user turns the network switch on and confirms it, never at launch.
