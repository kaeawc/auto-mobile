# Test files that run only on macOS hosts (owner rule 2026-10-23: iOS tests never
# run on Linux or Windows). `scripts/test-ts.sh` leaves them out of the unit and
# integration lanes on any non-macOS host; the macOS lanes (nightly CircleCI
# macOS Node Unit Tests, local macOS runs) still run every file. Mechanism and
# rationale: docs/design-docs/ci/macos-only-tests.md.
#
# Classification, in order:
#   1. The first rule below that matches a path wins. Format:
#        macos    <path-or-glob>  # reason
#        portable <path-or-glob>  # reason
#      `portable` keeps a file running everywhere; `macos` skips it off macOS.
#   2. Otherwise a path with an iOS token (ios, simctl, devicectl, simulator,
#      xcode, xcodegen, xcodebuild, xcrun, xctestrunner as a directory or
#      camelCase word) is macOS-only. This covers ~280 files with no rule.
#   3. Everything else runs everywhere. When unsure, keep it running: shared
#      parsers, tool schemas, broker and registry logic for both platforms, and
#      tests that scan repository files or workflows stay `portable`.
#
# test/lint/macOsOnlyTestClassification.integration.test.ts fails when a test
# whose direct imports are only iOS source has no rule here, when a rule
# matches nothing, and when a `portable` rule is not needed. Put the more
# specific `portable` rules before the broader ones.
